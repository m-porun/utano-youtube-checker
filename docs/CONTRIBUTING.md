# コントリビューションガイド

このプロジェクトへの変更は、安全性とレビュー可能性を保つため、以下のルールに従います。

## ブランチとマージ

- 作業ブランチは `feature/*`、`fix/*`、`docs/*`、`chore/*` を使用します。
- `main` へ直接 push してはいけません。必ず Pull Request（PR）を経由します。
- ユーザーの承認なしに、PR のマージまたはデプロイをしてはいけません。

## コミット

コミットメッセージの件名は、次の形式で50字以内にします。

```
[ADD|FIX|UPDATE|REFACTOR|TEST|DOCS|CHORE|SECURITY] 端的な日本語要約
```

既存履歴の `[ADD]` / `[FIX]` 形式を拡張したものです。本文には変更の「なぜ」を記載し、1コミットには1つの目的だけを含めます。

## Pull Request

PR テンプレートの次の必須項目をすべて記入します。

- 概要
- 主な変更と理由
- テストケース
- 外部公開・情報漏えいへの影響
- 確認してほしいこと

## コーディング規約

### Python

- ruff の lint と format に準拠します。
- 新規追加・変更する関数には型ヒントを付けます。既存コードは変更時に段階的に付与します。
- API・ファイルなどの I/O と純粋ロジックを分離します。
- 秘密情報は環境変数だけで扱い、ログに出力しません。

### TypeScript / React

- `strict` を有効にし、ESLint に準拠します。
- 外部から受け取る JSON は型ガードで検証します。
- `dangerouslySetInnerHTML` は使用しません。
- 外部リンクには `rel="noopener noreferrer"` を指定します。

### GitHub Actions

- `permissions` は最小権限にします。
- サードパーティ Action はコミット SHA に固定し、`# vX.Y.Z` のコメントを併記します。
- `pull_request_target` は使用しません。

## テスト方針

- ロジックを変更する場合は、必ずテストを追加します。
- バグを修正する場合は、先に再現テストを書きます。

## セキュリティと公開範囲

- Secrets は GitHub Secrets のみで管理します。
- デプロイ、公開範囲変更、Secrets の追加、リポジトリ設定変更は、必ずユーザーへ確認してから行います。
